Three unrelated launches this week all got filed under "agent memory," and that's the problem: they solve three different things. One is a handle you paste between chatbots. One is a smarter way to search what you already stored. One remembers how to do something, not what was said. Lump them together and "agent memory" keeps sounding like a solved category, when really none of these three pieces talk to each other.

[Segue](https://segue.ai/) is the smallest of the three: paste your context in, get a short code back, hand the code to a different model, and it loads the same context. No vector store, no retrieval — a pointer to a blob you wrote once. It launched on Show HN this week to a modest 21 points and 30 comments, worth noting next to the rest of the field: Engram, a Stanford spinoff also chasing agent memory, raised $98 million a few weeks ago, and Mem0, Letta, and Zep have been building funded memory layers for over a year. Segue solves copy-paste fatigue between ChatGPT and Claude. It doesn't touch the harder version — memory that updates itself, gets retrieved selectively, or outlives one handle's lifetime — the gap the funded players are actually chasing.

NVIDIA's [Nemotron 3 Embed](https://cobusgreyling.substack.com/p/nvidia-nemotron-3-embed) is aimed at that harder version: an open-weight embedding model built for retrieval — deciding what to pull back into context, not just where to store it. Three checkpoints shipped: an 8B model now first on RTEB, a retrieval benchmark, at an average NDCG@10 of 78.46; a cheaper 1B version; and a 4-bit NVFP4 variant tuned for Blackwell GPUs that keeps over 99% of the 8B's accuracy at roughly double the throughput. The number that matters most for agent memory is context length: 32,768 tokens per chunk, four times OpenAI's text-embedding-3 ceiling of 8,192, so a full multi-turn agent transcript embeds without getting chopped into pieces that lose the thread. It's self-hosted only, no API, so you trade per-token cost for running your own infrastructure — and it's not the best tool for every job, since people benchmarking code and API-doc search still rate Voyage's voyage-3-large ahead of it there. Long, messy conversation history is where this one earns its keep.

[OpenSpace](https://www.marktechpost.com/2026/07/25/building-self-evolving-ai-agents-with-openspace-using-skills-mcp-lineage-and-low-cost-reuse/), out of a Hong Kong university data science lab, is memory of a third kind: not facts, not conversations, but procedures. It sits in front of any MCP-connected agent, watches what a task actually took to complete, and turns that into a versioned SKILL.md file other agents can load directly — repairing it when a skill breaks because an API changed, rewriting it when a run succeeds particularly well, or minting a new one from a workflow nobody had captured before. Lineage lives in SQLite, so you can trace which skill file descended from which run. It's the same instinct I flagged in [an earlier post](/blog/the-tool-calling-glue-is-diy/) on tool-calling glue — vendors ship the raw primitives, MCP and skills-as-files, and leave someone else to build the durable layer on top — except this time it's an academic lab with 4.7k GitHub stars, not a solo developer. The project's own benchmark write-ups claim a 46% cut in token use and 4.2x more "income" than a baseline agent on the same backbone model; I found no independent replication of those numbers, so treat them as a vendor claim for now.

If I had to bet on one of these for agentique's own pipeline, it's Nemotron — the long context window is a genuine fit for embedding full article summaries and run logs, not just a cost play. Segue I'd use exactly once, for exactly the problem it names, and no more. OpenSpace I'd watch before I'd adopt: auto-repairing skills is a real idea, but I want to see what happens the first time AUTO-FIX silently patches something wrong before I hand it write access to my agents' playbooks.
